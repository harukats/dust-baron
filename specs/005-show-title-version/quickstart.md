# 検証ガイド: タイトル画面のバージョン表示

## 前提

実装後に実施する。リポジトリのルートで pnpm と依存を用意する。検証用ブラウザプロファイルを使い、普段のセーブに影響させない。画面契約は [contracts/title-version-ui.md](contracts/title-version-ui.md) を参照。

## 基本確認

1. 必要なら `pnpm install` を実行する。
2. `pnpm lint`、`pnpm typecheck`、`pnpm build` を実行する。build に既存 Vitest が含まれる。
3. `pnpm dev` を実行し、`http://localhost:8080` を開く。
4. package.json の番号と右下の表記が一致し、追加操作なしで見えることを確認する。
5. 1280×720、960×540、720×960 のウィンドウで、文字が欠けず右下に収まり、他の文字や操作部と重ならないことを確認する。
6. セーブなし・セーブあり・一時プレイで確認する。保存を拒否した状態から既存の一時プレイ選択を使い、下部通知と番号が重ならないことを確認する。
7. クリック・Space・Enter の各開始操作と、音声ボタン・M キーによる切り替えを別々に確認する。
8. 開発用 window.game から Title シーンを再起動して10回確認する。各回の表示数が1つ、DisplayList の要素数が初回と同じであることを確認する。

## 番号変更と配布ビルド

専用の一時コピーで package.json の version を `0.2.1-beta.1+build.1234567890` に変更し、再起動・再ビルドする。全文が表示され、通常版の番号が混在しないことを確認する。さらに接頭辞 `v` を除き40文字の境界値 `0.2.1-beta.1+build.123456789012345678901` でも確認する。通常版・プレリリース版・境界値の各表示が、ゲーム座標の16pxを維持して幅480px以内に収まり、1280×720・960×540・720×960で全文を判読できることを確認する。Text 自体を均等縮小しない。検証用の番号変更は成果物に含めない。

`pnpm exec vite preview --host 127.0.0.1` を実行し、案内された URL でビルド済み表示も確認する。開発用 window.game は本番ビルドでは使わず、画面から照合する。番号を取得する追加通信がないことをネットワーク記録で確認する。

対応するデスクトップ環境では `pnpm tauri dev` と `pnpm tauri build` の配布物で基本確認を行う。WebView ライブラリ不足で実行できない場合、理由・未確認の範囲を検証記録に残す。

## 性能と記録

[plan.md](plan.md) の条件で実装前後のフレーム間隔を比較する。ブラウザ・マシン・ウィンドウ寸法・負荷条件・測定値を記録し、3回のp95の中央値の増加が2ms以内であることを確認する。各回は最初の requestAnimationFrame 時刻を基準として集計から除外し、基準から30秒経過する最初のコールバックまで時刻差分を収集する。昇順に並べたN件の0始まり添字 `ceil(0.95 × N) - 1` をp95とする。タブを前面に置き、測定中は入力・リサイズ・別の検証を行わない。実装前後で同じ測定スクリプトを変更せず使用し、スクリプトと各回の生の取得値を機能ディレクトリ内に保存して validation.md から参照する。

検証結果は機能ディレクトリの validation.md に日本語で残す。コマンドの結果、通常版とプレリリース版の表記、画面寸法、一時プレイ、開始・音声操作、再起動10回、性能比較、デスクトップ確認の実施状況を記載する。未実施は合格として扱わない。
