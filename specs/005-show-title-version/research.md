# 調査結果: タイトル画面のバージョン表示

## 1. 番号の取得

**決定**: Title が `package.json` の `version` を直接名前付きインポートする。型検査には `resolveJsonModule: true` を指定する。

**理由**: 既存 Vite の JSON 名前付きエクスポートを利用でき、情報源を一本化できる。取得用 HTTP リクエストや実行時の Node API が不要。config の調整値を除けば変更は2ファイルで済む。

**比較した案**: Vite の define は取得設定とグローバル型宣言を増やす。番号の手書きは更新漏れにつながる。実行時 fetch はサブパス配布とオフライン利用に不要な依存を追加する。Tauri API はブラウザ版と共通化できない。

**根拠**: `tsconfig.json`、`vite.config.ts`、`package.json`、ローカル Vite の JSONOptions 型定義。専任の調査エージェントが取得案を比較し、追加依存が不要であることを確認した。

## 2. 配置と長い番号

**決定**: 既存 `label()`、原点 `(1, 1)`、右余白20・下余白16、文字サイズ16、色 `COLOR.sub` を使う。調整値は config に置く。対応範囲は接頭辞 `v` を除き40文字以内とし、文字サイズ16pxを維持する。Text 自体の均等縮小は行わず、最大幅480以内に収まることを検証する。

**理由**: 既存の太字等幅フォントと暗い輪郭を再利用できる。Scale.FIT はゲーム座標全体を拡大縮小するため、追加のリサイズ購読は不要。一時プレイ通知は左側740pxに収まり、右下の480pxと分離できる。

**比較した案**: DOM 表示はキャンバスとの位置合わせが増える。固定の左原点は番号が長いと右端からはみ出す。省略は番号全文の要件を満たさない。通常の番号には不要な複数行表示は採用しない。無制限の均等縮小は長い番号の可読性を損なうため採用しない。

**根拠**: `src/ui.ts` の label/addTemporaryNotice、`src/scenes/Title.ts`、Phaser text-and-bitmaptext スキル。

## 3. シーンの寿命

**決定**: create 時に1つ作成し、シーン管理の破棄処理を使う。

**理由**: Phaser の DisplayList.shutdown は登録オブジェクトを破棄し、リストを空にする。追加フィールド・購読・タイマーを持たないため、番号固有の解除処理は不要。

**比較した案**: 毎フレーム更新は不変の情報に不要。シーンを越える Text のキャッシュは寿命管理を複雑にする。

**根拠**: Phaser scenes スキル、`node_modules/phaser/src/gameobjects/DisplayList.js` の shutdown。

## 4. 検証

**決定**: 既存静的チェック・テスト・ビルドと画面確認を行い、軽量な性能比較と再起動確認を記録する。性能測定は同じスクリプトの requestAnimationFrame 時刻差分を用い、p95を昇順の0始まり添字 ceil(0.95 × N) - 1 で算出する。3回のp95の中央値を比較し、生の取得値も保存する。測定条件の詳細は plan.md に定義する。

**理由**: 主なリスクは文字列の取得、配置、入力への影響と重複であり、画面上の確認が適する。ゲームルールの変更はない。

**比較した案**: 文字列連結だけのユニットテストは得られる証拠が少ない。デスクトップ未実施を Web 検証で代替したことにはしない。

未解決事項はない。採用した API はインストール済みのコードとスキルで確認した。
