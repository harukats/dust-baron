**作業ブランチ**: `004-add-gold-cache` | **日付**: 2026-10-03 | **仕様**: [spec.md](spec.md)

**入力**: `specs/005-show-title-version/spec.md`

セットアップが返した機能識別子は `005-show-title-version`。実際の Git ブランチは上記のとおりであり、仕様ディレクトリとは独立して管理する。この計画ではブランチを変更しない。

## 概要

タイトル画面右下に `v` + `package.json` の `version` を表示する。`Title.ts` で番号を直接インポートし、既存の `label()` で静的な Text を1つ作成する。`tsconfig.json` に `resolveJsonModule` を追加し、表示調整値を `config.ts` にまとめる。

## 技術的背景

- **言語・バージョン**: TypeScript 7 系、ES2022、明示的な `.ts` import。
- **主要依存**: Phaser 4.2 系、Vite 8 系、pnpm。追加依存なし。
- **保存領域**: 番号はパッケージのメタデータ。セーブや設定への追加なし。
- **検証**: Biome、型検査、既存 Vitest、ビルド、ブラウザ画面確認。低リスクの表示変更なので自明なユニットテストは追加しない。
- **対象**: ブラウザと Tauri 2 の共通 Web ビルド。
- **種類**: 既存ゲームのタイトル UI。
- **性能目標**: 通常プレイの60 FPS目標を維持。Text は `create()` 時のみ生成し、毎フレームの文字更新やストレージアクセスを追加しない。
- **制約**: 1280×720、Scale.FIT、相対アセット URL、既存セーブ互換性を維持。
- **規模**: タイトル1画面、Text 1つ、実装変更3ファイル。

## フェーズ1: 設計

- Title から `../../package.json` の `version` を名前付きインポートする。JSON の拡張子は `.json` のままとする。
- config に `TITLE_VERSION_UI` を設け、右余白20、下余白16、文字サイズ16、色 `COLOR.sub`、最大幅480を定義する。
- create 内で背景や主要 UI の作成後に `label()` を呼び、座標 `(WIDTH - 20, HEIGHT - 16)`、原点 `(1, 1)` で置く。インタラクティブ化・点滅・イベント購読はしない。
- 対応する番号は接頭辞 `v` を除き40文字以内。Text の独自の均等縮小を行わず、ゲーム座標の文字サイズ16pxを維持する。通常版・プレリリース版・40文字の境界値が幅480px以内に収まり、1280×720・960×540・720×960で全文を判読できることを画面で確認する。Scale.FIT によるゲーム全体の拡大縮小は維持する。41文字以上は対象外とする。
- 幅480以内なら左端は780以上となり、左端から740までの一時プレイ案内と重ならない。
- Text はローカル変数だけで扱う。DisplayList の終了処理に破棄を任せ、再表示時に1つだけ作り直す。

データの制約は [data-model.md](data-model.md)、画面契約は [contracts/title-version-ui.md](contracts/title-version-ui.md)、検証操作は [quickstart.md](quickstart.md) を参照。

## 検証と性能比較

実装前後を同じマシン・Chromium・1280×720・通常保存モード・音声OFFで比較する。タイトル表示後5秒待ち、30秒間のフレーム間隔を3回測定し、p95 の中央値を比較する。合格基準は変更前からの増加が2ms以内。実測前に60 FPS達成を断定しない。

測定は `requestAnimationFrame` コールバックの時刻の差分を使う。各回の最初のコールバックは基準時刻とし、集計から除外する。基準時刻から30秒経過する最初のコールバックまで差分を収集する。N件の取得値を昇順に並べ、0始まりの添字 `ceil(0.95 × N) - 1` の値をp95とする。3回のp95を昇順に並べ、中央の値を比較する。タブを前面に置き、測定中は入力・リサイズ・別の検証を行わない。

実装前に同じ取得・集計処理を持つ測定スクリプトを用意し、実装後も変更せず使用する。測定スクリプトを `frame-probe.js`、各回の生の取得値を `frame-before.json` と `frame-after.json` に検証用成果物として機能ディレクトリ内へ保存し、validation.md から参照する。ブラウザ情報・マシン情報・各p95・中央値・前後差も記録する。

タイトルを10回再起動し、毎回番号の Text が1つ、DisplayList の要素数が初回と一致することを確認する。番号取得の追加通信が0件であることも確認する。通常・縮小・縦長、一時プレイ、セーブ有無、長い接尾辞を確認する。

`pnpm lint`、`pnpm typecheck`、`pnpm build`（既存テストを含む）を実施する。ブラウザ版の開発表示とビルド済み表示を確認する。デスクトップ版の操作確認は対応環境で行い、ローカルの WebView ライブラリ不足がある場合は未実施理由を記録する。Web の検証だけでデスクトップ確認済みとはしない。
