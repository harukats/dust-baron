# データモデル: ユニットテストを Vitest へ移行

ゲームの永続データと実行時 `State` は変更しない。この機能で扱うデータは開発時のテスト定義と実行結果のみ。

## テスト定義

| 属性 | 内容 | 制約 |
|------|------|------|
| ファイル | `src/*.test.ts` の既存3ファイル | `src/**/*.test.ts` に一致するファイルのみ標準実行の対象 |
| 名前 | 各テストの既存名 | ファイル内で失敗箇所を判別できること |
| 検証内容 | 既存の期待値と不変条件 | 移行による削除・緩和をしない |

## 実行結果

| 属性 | 内容 | 制約 |
|------|------|------|
| 実行件数 | 探索と絞り込みの後、実際に実行されたテスト数 | 標準実行では既存件数を下回らない。全件 skipped を含む0件は失敗 |
| 成否 | 各テストとコマンド全体の結果 | 1件でも失敗したらコマンドは失敗 |
| 失敗情報 | テスト名と失敗理由 | 出力から両方を特定できること |

## 関係と状態遷移

1. 標準コマンドはユニットテスト定義だけを探索する。Playwright E2E は別コマンドで扱う。
2. 実行は探索→実行→結果表示→終了の順で進み、監視状態に遷移しない。
3. テスト結果は `pnpm build` と CI の成功/失敗へ伝播する。
4. `storage.test.ts` のテストごとの状態初期化と後片付けを維持し、テスト間で保存状態を共有しない。
