# 機能仕様書: ユニットテストを Vitest へ移行

**作業ブランチ**: `003-migrate-unit-tests-vitest`

**作成日**: 2026-10-01

**ステータス**: ドラフト（仕様品質検証済み）

**入力**: GitHub Issue #7「ユニットテストをVitestへ移行したい。」

## Clarifications

### Session 2026-10-01

- Q: Vitest への移行に合わせて、憲章の `node:test` 指定も Vitest に改定しますか？ → A: 憲章の指定も Vitest に改定する。

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー1 - 既存のユニットテストを実行する (優先度: P1)

開発者は一つの標準コマンドで既存のゲームルールと保存処理のテストを実行し、失敗した条件を特定できる。

**優先する理由**: 移行で既存の回帰検出能力を失うと、ゲームの進行と保存データを安全に変更できない。

**独立したテスト**: 全ユニットテストを実行し、従来と同じテスト項目が成功することを確認する。

**受け入れシナリオ**:

1. **前提** 依存関係の導入が完了している、**操作** `pnpm test` を実行する、**結果** 既存の全ユニットテストが Vitest で実行され、失敗があればコマンドが失敗を返す。
2. **前提** テストの期待値が誤っている、**操作** `pnpm test` を実行する、**結果** 該当テストの失敗理由を確認できる。
3. **前提** ブラウザ操作の検証も別途存在する、**操作** `pnpm test` を実行する、**結果** ユニットテストだけが実行され、ブラウザ操作の検証は従来の専用コマンドで実行できる。

---

### ユーザーストーリー2 - 対象を絞って確認する (優先度: P2)

開発者は変更箇所に関係するテストファイルまたは名前を指定し、短い反復で動作を確認できる。

**優先する理由**: 日常の修正で全件実行だけを強制すると、失敗箇所を探しにくい。

**独立したテスト**: ファイルとテスト名を指定し、対象だけが実行されることを確認する。

**受け入れシナリオ**:

1. **前提** 複数のテストファイルがある、**操作** 一つのファイルを指定して実行する、**結果** そのファイルのテストだけが実行される。
2. **前提** 指定したファイルに複数のテストがある、**操作** 名前で絞って実行する、**結果** 一致するテストだけが実行される。

### エッジケース

- テストが一件でも失敗した場合、ローカルと CI の双方で成功扱いにしない。
- テスト対象が存在しない指定は成功扱いにしない。
- テストへの移行によって、ゲームの実行時の挙動や保存形式を変更しない。

## 要件 *(必須)*

### 機能要件

- **FR-001**: 既存の全ユニットテストを Vitest で実行できなければならない。
- **FR-002**: `pnpm test` は一度だけ実行して終了し、テスト失敗時に失敗を返さなければならない。
- **FR-003**: 開発者はファイルとテスト名で実行対象を絞れなければならない。
- **FR-004**: ビルドと CI の既存のテストゲートは移行後も全ユニットテストを実行しなければならない。
- **FR-005**: 開発者向け手順は新しいテスト実行方法と一致しなければならない。
- **FR-006**: 移行後も既存テストの検証内容とゲームの実行時挙動を維持しなければならない。
- **FR-007**: 標準コマンドはユニットテストだけを対象とし、既存のブラウザ操作テストの実行方法を維持しなければならない。
- **FR-008**: プロジェクト憲章に記載されたユニットテストの実行基盤も Vitest に改定し、移行後の運用方針と一致させなければならない。

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: 既存のユニットテスト全件が新しい標準コマンドで成功する。
- **SC-002**: テストを一件意図的に失敗させた検証で、標準コマンドとビルドの両方が失敗を返す。
- **SC-003**: ファイル指定と名前指定の各操作で、対象外のテストの実行件数が0件になる。
- **SC-004**: 移行前後で既存テストの検証項目数が減少せず、ゲーム実行時の挙動変更が0件になる。
- **SC-005**: 失敗したユニットテストについて、出力からテスト名と失敗理由を特定できる割合が100%になる。
- **SC-006**: 移行後の憲章と開発者向け手順に残る、旧テスト実行基盤を使う指示が0件になる。

## 前提と依存関係

- Issue #7 は既存ユニットテストの実行基盤の移行を指し、新しいゲーム機能やブラウザ E2E テストの移行は対象外とする。
- 現行のテスト内容、標準テストコマンド、ビルドと CI のゲートを前提とする。
- テストの実行に必要な開発用依存関係を利用できる環境を前提とする。
- 憲章の改定は、既存のレビュー手順とガバナンスに従って扱う。
