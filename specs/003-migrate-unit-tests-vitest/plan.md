# 実装計画: ユニットテストを Vitest へ移行

**ブランチ**: `003-migrate-unit-tests-vitest` | **作成日**: 2026-10-01 | **仕様**: [spec.md](spec.md)

**入力**: `specs/003-migrate-unit-tests-vitest/spec.md`

## 概要

既存のユニットテスト3ファイルを Vitest で実行し、`pnpm test`、ビルド、CI の失敗検出を維持する。探索対象を `src/**/*.test.ts` に限定して Playwright の `tests/e2e/*.spec.ts` を除外する。既存の厳密なアサーションとゲーム実装を保ち、依存・設定・開発者向け説明を更新して、改定済みの憲章に合わせる。

## 技術コンテキスト

**言語/バージョン**: TypeScript 7.0.2、Node.js 26（CI）、明示的な `.ts` import

**主要な依存**: Vite 8.3.0、Vitest 5.0.2（追加予定）、pnpm 12.5.1（`packageManager`）

**保存**: 変更なし。ゲームの保存形式と `storage.ts` の責務を維持する。

**テスト**: `src/*.test.ts` の3ファイル（動的生成を含む29件）、既存 Playwright E2E は別コマンド。型検査、Biome、ビルドを維持。

**対象環境**: Node.js 26 のローカル/CI、共通 Web ビルドを使う配布手順

**プロジェクト種別**: Phaser 4 の Web ゲームと Tauri デスクトップシェル

**性能目標**: ゲーム実行時の性能は変更対象外。標準テストコマンドは1回実行で終了し、監視状態に残らない。

**制約**: ビルドと CI のテストゲートを維持する。E2E をユニットテストとして実行しない。失敗や実行件数0件を成功扱いにしない。ゲーム実行時の挙動を変更しない。

**規模/範囲**: 既存ユニットテスト3ファイルとテスト設定・依存・開発者向け文書。改定済み憲章との整合も確認する。ブラウザ E2E とゲームロジックは移行対象外。

## 実装の順序と検証

1. 移行前の実行件数、`pnpm test`、型検査、lint の結果を記録する。
2. Vitest を開発依存へ追加し、ロックファイルを更新する。専用設定で `src/**/*.test.ts` と Node 環境を指定する。標準レポーターに加え、終了時に実行済みテストを数えて0件なら失敗終了する小さなレポーターを設定し、設定も型検査対象に含める。
3. `node:test` の `test`/`beforeEach`/`afterEach` import を Vitest に変更する。厳密な `node:assert/strict` は結果の意味を保つため維持する。ゲーム本体は変更しない。
4. `pnpm test` を `vitest run` にし、既存 `build` と CI の `pnpm test` 呼び出しを維持する。対象0件を成功にする設定は加えない。
5. README、AGENTS、テスト内の古い実行説明を更新する。憲章 2.0.0 の Vitest 指定と同期影響レポートの削除を確認する。過去の仕様文書は履歴として維持する。
6. [quickstart.md](quickstart.md) の全件、絞り込み、対象外、失敗伝播、型検査、lint、ビルドを実施し、結果を日本語で記録する。

## 複雑性の追跡

| 衝突・追加 | 必要な理由 | 採らない案と理由 |
|-----------|------------|------------------|
| 憲章 2.0.0 との整合確認 | 先行する憲章改定と実装・開発手順を一致させる | 旧版への再変更は改定済みの規則に違反する |
| Vitest 開発依存と専用設定 | Unit と Playwright の探索を分離し、CI で安定して実行する | 引数による探索制限だけでは直接実行時に混在しやすい |
| 実行0件を検出する追加レポーター | Vitest 5 は名前指定に一致するテストがない場合、全件 skipped でも成功終了する。仕様の失敗判定を守る | 既定の終了コードだけでは名前指定の0件を検出できない |
