# 契約: デスクトップ起動と表示通知

## プレイヤー向けの契約

| 入力 | 結果 | 仕様 |
|---|---|---|
| 初回起動 | 1つのゲームを開始 | FR-001 |
| 追加起動・同時起動 | 所有者だけ継続、追加側はゲームを開始せず終了 | FR-002・003 |
| 最小化/背面で追加起動 | 既存mainを表示・復元しフォーカスを試みる | FR-004 |
| 正常終了/強制終了後の起動 | 自動的に所有権を取得し通常起動 | FR-005 |
| 表示通知失敗 | 多重起動を許可しない | FR-001 |

## 内部通知の契約

アプリ専用。一般向けのAPIやゲーム側のJS APIとして公開しない。

- 待受は `127.0.0.1` のOS割当ポートのみ。
- endpointはASCIIの `1 <port> <token>\n`。portは1〜65535、tokenは32バイト乱数の64桁小文字16進表現。256バイトを超えるデータは拒否する。
- 要求は `ACTIVATE 1 <token>\n`。上限128バイト。認証値が一致した表示要求だけを受理する。任意の引数、ファイルパス、ゲーム操作、外部URLを受理しない。
- 受理応答は `OK\n`。これは表示要求を受領したことを示し、OSがフォーカスを許可したことを保証しない。不正な要求は副作用なく接続を閉じる。
- 接続・読み書きには各200msのタイムアウトを設定し、追加側の全再試行を2秒以内に制限する。各試行には残り時間を適用する。待受側も1接続の読み込みを200ms以内に打ち切る。
- 所有者は新しいendpointを公開する前に待受を確保する。追加側はendpointが不完全なら期限内で再読込する。古いendpointへ到達してもtokenが一致しなければ要求は成立しない。
- 起動準備中は表示要求を1つ保持する。Tauriメインスレッドでmainに対し `show()`、`unminimize()`、`set_focus()` を個別に試す。1つの失敗で後続操作を省略しない。
- macOSのFinder・Dockからの再オープンは `RunEvent::Reopen` で受け取り、同じ表示復元処理へ接続する。起動準備中は集約し、終了中は無視する。
- 待受は非ブロッキングとし、接続がない場合は終了通知を待つ。終了通知で待機を即座に解除し、接続処理には読み書き全体で200msの総期限を設ける。ゲームの更新ループには待機処理を追加しない。終了時は新規要求を停止し、停止通知、スレッドのjoin、endpoint削除、ロック解放の順で処理する。接続なし・要求途中・通知処理中の各状態から1秒以内に終了処理を完了する。メインスレッドへの表示要求配送は完了待ちをせず、終了時のjoinとの相互待ちを避ける。

## エラーと診断

排他・保存先・乱数・待受準備に失敗した初回起動はゲームを開始せず、原因を標準エラーへ出す。追加側の通知期限切れはゲームを開始せず終了し、診断を残す。トークンやセーブをログ出力しない。GUI専用の新たなエラーダイアログは作らない。
