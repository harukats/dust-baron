# 調査結果: ゴールド・キャッシュ

調査日: 2026-10-03。既存コード・インストール済みPhaserスキル・画像生成ツールの契約を一次資料として確認した。Phase 0 の研究は別エージェントにも委任し、コア・時間境界・回帰検証の所見を統合した。

## 1. 専用アセットの生成経路

**決定**: 関連スキル `imagegen` の組み込み `image_gen` を使って新規透過PNGを生成し、最終画像を `public/assets/gold-cache.png` に保存する。実行時のプロンプト・生成経路・選択結果を記録する。

**理由**: Phaser Game Agent の `generate_sprites` は利用可能だが、ツール契約はCDN URLをそのまま使う運用を指定している。このリポジトリは同梱ローカルアセットと相対URLが要件なので、ユーザーが認めた関連スキル経路を選ぶ。組み込みツールは透明背景とローカル参照画像を扱え、新しい外部実行環境・SDK依存を不要にする。

**比較案**: Phaser Game Agentのクラウドプロジェクト新規作成・CDN実行時参照は採用しない。クロームの単なる色変更は仕様を満たさない。手描きSVG・コード描画の代替も専用ラスタースプライトの生成要求に合わない。CLI/API経路はユーザーが明示選択した場合のみ使用する。

**参照**: `/home/harukats/.codex/skills/.system/imagegen/SKILL.md`、同 `references/prompting.md`、Phaser Game Agent `generate_sprites`・`establish_game_style` のツール定義。現在の `chrome-cache.png` は128×128の物資・弾薬・金庫の集合である。既存画像を目視し、ゴールドでは装飾された金色の回収容器を中心とする異なるシルエットにする。

## 2. 画像表示と読み込み

**決定**: 静止PNGをPreloaderで読み込み、goldキーをPIXEL_TEXTURESへ追加してNEARESTを設定する。Gameでは既存の `fitImage(..., 96)` と `Image` を使用する。

**理由**: 静止画にフレームアニメーションは不要。Imageは既存のTween浮遊・入力を利用できる。文字・粒子のためグローバルpixelArt設定は変更しない。

**比較案**: SpriteSheetや新たなアニメーション管理は状態・アセット量を増やす。既存chromeのTintだけでは専用絵柄を満たさない。

**参照**: `.agents/skills/phaser-loading-assets/SKILL.md`、`.agents/skills/phaser-sprites-and-images/SKILL.md`、`.agents/skills/phaser-scenes/SKILL.md`、`src/scenes/Preloader.ts`、`src/ui.ts`。

## 3. 抽選と報酬

**決定**: `selectCacheKind(roll)` は0以上1未満の値で0.1未満をgoldにする。種類は出現時に固定する。クロームだけが50%即時報酬・50%7倍を抽選し、goldは報酬抽選を行わず必ず777倍を付与する。種類抽選の不正値はchrome、chrome報酬抽選の不正値は報酬なし（none）とし、資源・既存倍率・期限を維持する。

**理由**: 表示と回収結果の一致、確率境界の決定的テスト、設定値の一元化を実現する。即時報酬は `max(perSecond(s)*60, clickPower(s,perSecond(s))*30)` の現行式を保つ。

**比較案**: 回収時に種類を再抽選すると専用画像と報酬が食い違う。独立した出現タイマーは確認済みの出現方式と不一致。

## 4. 倍率と時間

**決定**: `run.frenzyMult` と `run.frenzyEndsAtMs` を正として、純粋関数で有効倍率・取得遷移を計算する。7→777は置換、777→7は終了時刻も維持、同倍率は20秒へ更新。有効なのは `now < endsAtMs` のときだけ。

**理由**: 永続Stateと一時効果を分離でき、既存セーブ互換を維持する。期限は既存 `run.now()` と同じ絶対時刻であり、非表示中も進む。

**比較案**: 倍率の積み重ね、弱い効果の予約、独立した7倍・777倍タイマーは仕様と不一致。出現待ちのdelta累積は維持し、無関係な時間仕様は変更しない。

## 5. 通常採掘とライフサイクル

**決定**: 通常採掘量は `clickPower(s, perSecond(s))` を維持する。砂嵐は自動生産だけに作用する。`initializeRun`・`resetRun`・`Game.create` で倍率と期限を対で解除する。マウス・SPACEは同じdig経路で計算する。

**理由**: 現状GameのdigPowerは砂嵐込みの生産量を渡していない。新倍率だけを足し、既存ゲームルールを変えない。シーン再利用時もコンストラクターに依存しない。

**比較案**: 永続セーブに倍率を足すと復元ルールや移行が必要になる。Sceneの `cache` フィールドはCacheManagerを上書きするため使用しない。

## 6. 検証・性能

**決定**: 境界・競合・経済をVitest、画像・入力・音声・復帰をPlaywrightで検証する。既存headed性能プローブを拡張し、条件・時間・合格基準はplanに定義する。

**理由**: ブラウザを必要としないコアと実際の操作結果をそれぞれ確認できる。既存ui-check/runtime-checkが期限だけを直接設定するため、新倍率フィールドの設定も更新する。ui-checkのクローム確認は出現種類と回収報酬を対象呼び出し中だけ固定し、確認後に画面を保存する。性能測定は砂嵐15秒・採掘効果20秒の再付与周期を揃え、変更後通常を変更前通常、変更後7倍・777倍を変更前7倍と比較する。

**比較案**: 乱数を大量試行するだけの確率検証は不安定。純粋な閾値境界と表示種類に対応する回収結果を検証する。未計測の性能保証は行わない。

未解決の調査事項なし。画像の最終品質は後続の生成・表示検証で合格判定する。
