# 保存・セッション契約

## 保存の互換性

保存キーは `dust-baron-save-v1`。JSONは既存Stateのscrap/total/clicks/owned/pick/won/playTime/lastSaveを維持する。
CreditsへのUI変更では保存変換や価値の変更を行わない。型と復旧規則は [データモデル](../data-model.md) に従う。
自動保存は5秒ごと、購入成功時、再開時の離席加算後。非表示と終了時は精算後に可能な保存を行う。

保存APIは呼び出し時にlocalStorageへアクセスし、モジュール読み込み時にDOMやブラウザを参照しない。
書き込み成功と失敗を区別できる結果を返し、失敗でライブrunを破壊しない。
正常な最終保存を復旧基準とし、終了イベントや失敗した書き込みを成功扱いしない。

## 時間の二つの経路

- **ライブ経路**: accountedAtMsから現在時刻までを100%で精算。非表示・最小化にも適用し、2時間で打ち切らない。同じカーソルの区間を再計上しない。
- **再開経路**: ownedを取得後、run.stateがnullのときだけ保存を解析し、正常なlastSaveからの時間が30秒以上なら通常生産量×min(離席秒数,7200)×0.5を加算する。不正日時・未来時刻の負時間は0。

離席収入はearnで残高と累計に反映し、即時保存する。保存不能時の永続的な再受領防止は保証できないが、同じライブrun内では二度与えない。

## プレイ権の外部API契約

ロック名は保存キーに対応する `dust-baron-save-v1:play` とし、排他・ifAvailableで取得する。
取得結果はowned/blocked/unavailable。待機列・steal・期限付き横取りは使わない。
所有コールバックから保持Promiseを返し、結果通知Promiseとは分ける。非表示でも保持する。

ロック取得前に共有進行の読込・変更・初期化を始めない。後の画面はブロックUIだけ表示する。
ロック未対応や例外では共有保存へアクセスしない。所有後のlocalStorage失敗ではメモリ内プレイを継続する。
pagehide・破棄・HMRでは旧処理を停止してから解放する。bfcache復帰は再取得・再読込する。

## 公開インターフェースの範囲

HTTP API、外部認証、クラウド保存、セーブのユーザー向けimport/exportは追加しない。
外部インターフェースは英語UI、既存localStorage保存、同じ保存領域でのWeb Locks連携である。
開発専用window.gameは既存のまま検証に利用し、製品版には公開しない。
