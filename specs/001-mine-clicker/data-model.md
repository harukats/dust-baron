# データモデル: Mine Clicker

## 永続化するプレイヤー状態

既存 `State` とJSONのフィールド名を維持する。UIのCreditsは `scrap` に対応する。新規サーバーや通貨変換はない。

| フィールド | 型・単位 | 初期値 | 検証・意味 |
| --- | --- | --- | --- |
| scrap | number / Credits | 0 | 有限・非負。利用可能残高 |
| total | number / Credits | 0 | 有限・非負。累計収入。正常な値は保持し、既存のtotal以上scrapの整合を維持 |
| clicks | number / 回 | 0 | 非負整数。手動採掘回数 |
| owned | number[6] | 各0 | GENSの順序で各種類の非負整数。種類単位で復旧 |
| pick | number / レベル | 0 | 非負整数。Forge Pick |
| won | boolean | false | Dust Crownの一度だけの達成 |
| playTime | number / 秒 | 0 | 有限・非負。ゲーム開始後の経過 |
| lastSave | number / epoch ms | 0 | 正常な成功保存日時。0は未保存・無効の印 |

不正・欠落した項目は初期値へ戻す。整数項目の小数は切り捨てない。配列の余剰要素は読まず、不足部分を0にする。
rootはnull・配列ではないオブジェクトで、上記の既知進行項目を少なくとも1つ持つ必要がある。不明項目は無視する。
金額は小数を保持する。購入後に負の残高を作らず、整数項目は安全に整数加算できる範囲で受理し、範囲外はその項目だけ0にする。読み込み時に各ownedの生産量が非有限なら該当種類だけ0、通常採掘量が非有限ならpickだけ0にする。購入・収入の計算で非有限値や非有限の残高・累計を作る操作は拒否する。有限だが高額な価格を持つ正常な進行は保持する。

日時が無効なら起動時に現在時刻を基準に設定し、離席加算しない。未来日時は離席時間0とする。
正常な日時で再開した場合も、復旧後の所有数から通常生産量を再計算する。

## 生産定義と派生値

GENSのkeyを識別子、配列順を既存保存との対応に使う。キー・順序・6種類を今回変更しない。
名称、基本価格、基本毎秒収入、価格増加率、所有数閾値はconfigに置く。
派生値の現在価格、通常毎秒収入、採掘量、MAX数量は保存せず経済関数で導出する。

購入は対象・数量・合計費用をもつ操作で、成功時のみ残高と所有数を同時に更新する。
Forge Pickは残高とレベル、Dust Crownは残高とwonを同時更新する。

## 永続化しないライブ状態

| 概念 | フィールド候補 | 責務 |
| --- | --- | --- |
| ライブrun | state: State または null | シーンをまたぐ同じ進行 |
| 生産カーソル | accountedAtMs: number | 起動epochに単調経過を加えたライブ時計で、この時刻まで精算済み |
| ライブ時計 | now: () => number | 呼び出し側で注入。保存日時の実日時とは独立し、セーブに書かない |
| セッション | status: acquiring / owned / blocked / ephemeral / released | プレイと保存を許可する状態 |
| ロック | name、保持Promiseの解放関数 | 保存キーごとの排他。セーブに書かない |
| 一時効果 | stormEndsAtMs、frenzyEndsAtMs、cacheExpiresAtMs | 実時刻に基づく失効 |

カーソルは成功保存日時とは独立する。精算してからカーソルを前へ進め、同じ時刻の再精算は0とする。
生産・購入・採掘はownedとephemeralが実行できる。共有保存の読込・書込・削除はownedだけが実行する。blockedはStateを初期化・読み込みしない。ephemeralはnewStateからメモリ内runを開始し、離席収入を与えない。

## 状態遷移

1. 起動 → acquiring → ロック成功ならowned、競合ならblocked、API非対応・取得例外ならephemeral。
2. owned → 初回の保存解析 → 正常項目の復旧 → 必要なら離席加算 → 即時保存 → カーソル設定 → Title/Game。
3. ephemeral → 保存解析・離席加算なし → newStateとカーソル設定 → Title/Game。NEW RUNはownedとephemeralが確認後に実行できる。ownedは保存を削除し、ephemeralはメモリ内だけでnewStateに切り替える。
4. ownedとephemeralの各操作・非表示・復帰、およびownedの保存で未計上区間を精算する。画面が非表示でもownedまたはephemeralを維持する。
5. Game → Victory → Game / Titleはstateを保持し、離席計算を再実行しない。
6. pagehide・破棄 → 精算・ownedのみ可能な保存 → 処理停止・購読解除 → released。bfcache復帰に備えて終了前のセッション種別を保持する。
7. ownedのbfcache復帰はacquiringから再開する。ephemeralのbfcache復帰は同じメモリ内runへ戻り、未精算分を100%精算する。blockedは先行画面終了後の再読み込みでacquiringへ戻る。
8. ephemeralは画面存続中にownedへ昇格しない。再読み込み・終了では一時進行を破棄して再判定し、共有保存へ移行・合算しない。

## 主な不変条件

- 保存先ごとにownedは最大1画面。blockedとephemeralは共有保存を読み書き・削除しない。
- 同じ時間の通常生産と離席収入を重複加算しない。
- 生産率変更の前までを旧生産率で精算し、新しい率を過去に適用しない。
- 非表示中も正常な通常生産は100%。離席下限・上限・50%は閉じて再開したときだけ使う。
- 一時倍率は有効期限の区間だけに適用し、非表示中のイベントを大量再生しない。
- 正常な保存項目と既存残高の価値を維持する。不正日時は離席収入0。
